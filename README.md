# Голосования на Jetpack Compose

Общий бриф для обоих участников. В ветке `codex/list-and-state` готовы модель, список, общие данные и переходы. Экраны создания и голосования пока содержат только заготовки; их реализует `dobranitskiy`.

## Что делаем

1. Список голосований с кнопкой создания и открытием выбранного вопроса.
2. Создание: вопрос, два ответа, кнопка «Создать». Удалять пробелы по краям, запрещать пустые поля. После создания возвращаться к списку.
3. Голосование: две кнопки ответа и два счётчика. Каждое нажатие добавляет один голос — упрощение для демонстрации.

Данные только в памяти: перезапуск очищает их. Работают переходы и системная кнопка «Назад».

## Общий договор

Пакет: `com.example.seminarcompose`. Файлы Kotlin находятся в `app/src/main/java/com/example/seminarcompose/`.

Модель `Poll` — `data class`; все поля объявлены через `val`:

- `identifier: Int`
- `question: String`
- `firstAnswer: String`, `secondAnswer: String`
- `firstVotes: Int = 0`, `secondVotes: Int = 0`

Сигнатуры экранных функций; обе помечаются `@Composable`:

```kotlin
fun CreatePollScreen(
    onCreate: (String, String, String) -> Unit,
    onBack: () -> Unit
)

fun PollDetailsScreen(
    poll: Poll,
    onFirstVote: () -> Unit,
    onSecondVote: () -> Unit,
    onBack: () -> Unit
)
```

Порядок аргументов `onCreate`: вопрос, первый ответ, второй ответ. Форма хранит локально только введённый текст. Общий наблюдаемый список и переходы находятся в корневой функции интерфейса. При голосовании заменяем элемент списка через `copy(...)`; экраны отправляют события через переданные функции.

## Кто делает

| Участник | Ответственность |
|---|---|
| `stdems` | `Poll.kt`, `MainActivity.kt`, `PollListScreen.kt`: модель, общее состояние, переходы, список |
| `dobranitskiy` | `CreatePollScreen.kt`, `PollDetailsScreen.kt`: создание и голосование |

Ветки: `stdems` — `codex/list-and-state`, `dobranitskiy` — `codex/create-and-vote`. Перед началом работы напарник выполняет `git fetch origin`, `git switch codex/create-and-vote`, `git merge origin/codex/list-and-state`, затем заменяет тела двух экранных функций. Их имена и параметры сохраняет. Общую модель и чужие файлы меняем по согласованию. Готовый экран → коммит → push → Pull Request → взаимная проверка → объединение → обновление локального `main`.

## Простота и защита

Полные имена, стандартные компоненты Compose. Без комментариев, TODO/FIXME, `!!`, `Any`, сервера, базы, авторизации и лишних слоёв.

`remember` хранит данные между обновлениями интерфейса. `mutableStateListOf` делает список наблюдаемым. `copy` создаёт изменённую копию голосования, которой заменяем элемент списка. `when` выбирает экран, а `BackHandler` обрабатывает системную кнопку «Назад».

Оба проверяют несколько голосований, пустой ввод, счётчики и возврат. Каждый объясняет весь код: компоненты, события, состояние, навигацию и цепочку «кнопка → данные → экран». После обмена с другой парой готовим сравнение реализаций.

## Запуск

Клонировать репозиторий, открыть его корень в Android Studio. Выбрать Gradle JDK 21, установить Android SDK 36 и эмулятор. Дождаться Gradle Sync, выбрать конфигурацию `app` и нажать Run.
